# Отказоустойчивость сети из четырёх валидаторов (M2.5)

Результаты живых тестов M2.5 на CometBFT v0.40.0 + `yapd`: четыре валидатора с power 10 (кворум — больше 2/3
power, то есть 3 из 4) и одна full node без права голоса. Linux x86_64, все ноды на одной машине, P2P — через
прокси отказов на loopback. Значения сравниваются строго по высоте (`tests/integration/livenet.py`): block hash,
`Header.AppHash`, `block_results` и state root каждой ноды, а состояние — с независимой моделью на высоте каждого
ответа.

## 1. Инфраструктура отказов
- [`scripts/localnet/netfault.py`](../scripts/localnet/netfault.py) — непривилегированный TCP-прокси (asyncio,
  stdlib, без root, без изменения сетевых настроек машины) на **каждой направленной P2P-связи** i→j:
  `persistent_peers` ноды i указывают на порт прокси для (i, j), PEX выключен — другого маршрута нет.
- Через прокси не идут ни RPC (тестовый контроллер), ни ABCI (Unix socket `yapd`).
- Отказы включаются и выключаются во время работы (Unix socket, JSON): разделение на группы и восстановление;
  **односторонняя** задержка на каждое направление (RTT = 2×) с равномерным jitter и сохранением порядка TCP;
  периодические разрывы (flap); сброс TCP-соединений.
- **Потеря отдельных пакетов не моделируется**: для неё нужен tc/netem (root; модуль ядра не загружен).
  Сброс TCP-соединения — другой отказ и так и называется.
- Каждое событие пишется с временем UTC (`<dir>/faults.log`, тестовые действия — `<dir>/events.log`).
- Остановка и аварийное завершение процессов — SIGTERM/SIGKILL отдельно CometBFT и `yapd`; точки сбоя внутри
  Commit — только в отдельном `yapd-test-hooks`. Процессы привязаны к тесту (`PR_SET_PDEATHSIG`), уборка проверяется.
- Доказательство изоляции (сценарий `infra`): при изоляции всех нод — 0 пиров у каждой по `net_info`, 0 байт через
  прокси, попытки переподключения отклоняются прокси, блоков нет; RPC и ABCI Query при этом отвечают.

## 2. Потеря и восстановление кворума (`fault_quorum`)
| Шаг | Наблюдение |
|---|---|
| остановлен 1 валидатор | 30 из 40 power — блоки продолжаются |
| остановлен 2-й | 20 из 40 — ни одного блока за окно 25 + 10 с (опрос каждые 0,5 с после паузы на завершение начатого блока); `/chain` не меняется; консенсус ждёт следующую высоту в раунде 0 на шаге prevote: при половине power нет «+2/3 любых» prevote, поэтому `timeout_prevote` не запускается и раунд не растёт |
| tx через доступную ноду | CheckTx 0, tx в мемпулах обеих живых нод, но ни в одном блоке |
| возвращён 3-й | консенсус продолжается с той же высоты, ожидающая tx исполняется на ней |
| возвращён 4-й | все четыре синхронны; хеши, roots, результаты, состояние и награды совпадают; каждый блок подписан ≥ 3 валидаторами |

## 3. Разделения сети (`fault_partition`)
**3+1.** Все процессы работают. `net_info`: `{0:[1,2], 1:[0,2], 2:[0,1], 3:[]}`; через разрыв — 0 байт. Трое
финализируют, изолированный не финализирует ничего; tx большинства исполняется, tx изолированной стороны остаётся
в её мемпуле. После восстановления изолированный получает пропущенные высоты как решённые блоки (FinalizeBlock без
ProcessProposal) **через catch-up gossip консенсуса CometBFT** — работающая нода в v0.40.0 не возвращается в
blocksync (`adaptive_sync` выключен); blocksync проверяется сценариями рестарта (§6, §7). Затем он снова голосует
COMMIT, его tx исполняется.

**2+2.** Ни у одной группы нет кворума: 20 с ни одного блока ни на одной ноде, все в раунде 0 на шаге prevote.
Конфликтующие transfer с одним nonce приняты каждой группой (CheckTx 0/0) и не финализированы. После восстановления
исполнен ровно один, второй ушёл из всех мемпулов; балансы, nonce, supply точные.

**Конфликтующие финализированные блоки** проверяются в каждом сценарии: для каждой высоты, которую закоммитила хоть
одна нода, все ноды, у которых она есть, имеют один block hash и один state root. Расхождений не было ни разу.

## 4. Задержки и нестабильная связь (`fault_latency`)
Задержка — **односторонняя** на каждом направлении (RTT = 2×). 12 блоков на профиль, 3 transfer от разных
отправителей. Интервал — по настенному времени durable Commit у validator-0; включение — от отправки до Commit
включающего блока; доп. раунды — `LastCommit.round`; флаги A/C/N — на валидатора за профиль. Тихий прогон, Debug:

| Профиль | Блоков | Медиана | p95 | Доп. раунды | Включение tx, мс | A/C/N (v0; v1; v2; v3) |
|---|---|---|---|---|---|---|
| без отказов | 12 | 1189 мс | 1208 мс | 0 | 704–1063 | 0/11/0 у всех |
| 50 мс (RTT 100) | 12 | 1349 мс | 1371 мс | 0 | 829–1138 | 0/11/0 у всех |
| 150 мс (RTT 300) | 12 | 1936 мс | 2100 мс | 0 | 1436–1752 | 0/11/0 у всех |
| 300 мс (RTT 600) | 12 | 2838 мс | 2988 мс | 0 | 2448–4991 | 0/11/0 у всех |
| 150 ± 120 мс jitter | 12 | 1889 мс | 2034 мс | 0 | 1363–3031 | 0/11/0 у всех |
| разрывы 1 с каждые 10 с | 12 | 1139 мс | 7900 мс | 1 | 604–932 | 0/10/1; 0/11/0; 0/9/2; 1/10/0 |
| жёсткий: разрывы 2 с каждые 6 с | 8 из 12 за 180 с | 16 238 мс | 54 216 мс | 6 в 3 блоках | 795–1119 | 0/7/0; 0/7/0; 0/7/0; 0/6/1 |
| жёсткий: 1500 мс (RTT 3 с) | 2 из 12 за 180 с | 87 900 мс | — | 0 | 7859–95 924 | 0/1/0 у всех |

Умеренные задержки консенсус выдерживает без лишних раундов: интервал растёт примерно на 3 односторонние задержки
(proposal → prevote → precommit). Разрывы порождают NIL/ABSENT и лишние раунды. Оба жёстких профиля останавливают
сеть почти полностью; после нормализации связи она восстанавливается без расхождений (все проверки конца сценария).

## 5. Аварии (`fault_crash`, `fault_crash_disk`)
| Отказ | Наблюдение |
|---|---|
| SIGKILL `yapd` до durable Commit (`before_commit:H`) | durable H−1; CometBFT останавливается сам; рестарт → «Replay last block using real app» |
| SIGKILL `yapd` после durable Commit (`after_commit:H`) | durable H; рестарт → replay через mock app (повторного исполнения нет) |
| SIGKILL CometBFT | `yapd` продолжает работать; перезапуск одного CometBFT, штатный handshake |
| остановка только `yapd` (SIGTERM) | CometBFT завершается сам; оба перезапущены, догон |
| одновременная потеря двух нод (SIGKILL) | блоков нет; tx ждёт в мемпуле; после возврата консенсус продолжается, tx исполняется |
| последовательные аварии разных валидаторов | восстановление каждого |
| повторные SIGKILL отставшей ноды во время догона | догоняет после окончательного старта |

Во всех случаях: `priv_validator_state.json` не сбрасывался и только рос (проверка после каждого рестарта); ключи
не копировались и не менялись; на каждой ноде каждая высота закоммичена ровно один раз, без пропусков; награды
точные (нет двойной эмиссии); roots одинаковы; verify-state всех баз. `fault_crash_disk` — тот же сценарий на
btrfs (`/var/tmp`, реальная ФС с fsync); `/tmp` здесь — tmpfs. **SIGKILL проверяет падение процесса, а не потерю
питания.**

## 6. Full node без права голоса (`fault_fullnode`)
Пятая нода создаётся после 20+ блоков: свои ключи (не в наборе валидаторов), тот же `genesis.json` побайтно, пустые
базы. Подключается по P2P к четырём валидаторам, выполняет InitChain из genesis и синхронизируется через blocksync
(в прогоне — высоты 1..21, затем consensus); хеши и roots совпадают; Query точный; её tx получают все валидаторы и
исполняют; её адрес нет ни в одном LastCommit, состояние подписи не растёт, наград нет; её остановка не влияет на
блоки; после рестарта догоняет ≥ 10 блоков через blocksync.

## 7. Soak (`integration:soak`, только `ctest -C soak`)
Четыре валидатора + full node (добавлена после старта, синхронизирована от genesis), все P2P-связи через прокси,
`timeout_commit = 300ms`, seed 20261124: 16 отправителей (ключи выводятся из seed и никуда не пишутся; счета — в
genesis), Transfer и Burn строит и подписывает независимая Python-реализация (`tools/refgen`), конвейеры
последовательных nonce, контролируемые повторы тех же байтов и конфликты одного nonce, ресинхронизация nonce после
потери мемпула при рестарте. Расписание отказов из seed: разделения 3+1 и 2+2, потеря кворума, SIGKILL одного и
двух валидаторов, остановка валидатора, рестарт full node, задержка связей.

| Метрика | Значение (Debug, чистый прогон) |
|---|---|
| Блоков / исполнено транзакций | 1003 / 42 462 (из них 4 164 Burn), 44 789 отправок |
| Отказов | 9: partition 2+2 ×2, 3+1, потеря кворума, SIGKILL одного, SIGKILL двух, остановка, рестарт full node, задержка |
| Время | 591 с; интервал между блоками: медиана 470 мс, p95 550 мс, максимум 15,6 с (потеря кворума) |
| Финал | все 5 нод на высоте 1030; на общей высоте 1029 block hash `0F2F8E6B…352BD8`, root `01b56a9a…4ee9dc` |
| verify-state | все 5 баз: высота 1030, root `caf7c001…e39dda` |
| Эмиссия | minted 2 604 016 YAP (genesis 2 602 010 + 2 × 1003), сожжено 31,57 YAP; модель = все ноды |

Каждая общая высота сравнивается на всех пяти нодах (block hash, результаты, roots); каждый ответ Query — с
моделью. Отчёт прогона (seed, оба genesis, все транзакции, расписание и события отказов, метрики, финальные хеши,
логи нод — без приватных ключей) пишется в `<base>/report/`; сеть с ключами удаляется после успеха.

Первый полный прогон (до перевода планировщика на монотонные часы) пережил **сон хоста на 39 минут** посреди
нагрузки: после пробуждения сеть продолжила работу без расхождений (1004 блока, 41 978 транзакций, все пять баз
сошлись), но настенные часы сжали расписание отказов — поэтому теперь используется монотонное время.

## 8. Что не проверено
- Потеря отдельных пакетов (нужен netem/root); разные хосты и реальная сеть; асимметричные разделения (односторонняя
  потеря связи); разделение длиннее нескольких минут.
- Byzantine-поведение, evidence на живой сети, slashing — вне scope.
- Отключение питания (SIGKILL ≠ потеря питания; fsync LMDB и CometBFT не проверялся физически).
