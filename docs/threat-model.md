# Модель угроз YapChain

Статусы: **DECIDED** — утверждено, **PROPOSED** — предлагается, **OPEN** — требует решения.
Все меры ниже — **PROPOSED**, если не указано иное.

## 1. Активы и допущения

**Активы**: балансы, корректность `total_supply`, непрерывность и неизменность истории, доступность сети,
ключи пользователей, валидаторов и эмитентов, Rewards Pool.

**Допущения**:
- не более 1 из 4 валидаторов византийский (`f < n/3` по power);
- SHA-256 и Ed25519 стойкие;
- CometBFT корректно реализует Tendermint (внешняя зависимость);
- сеть частично синхронна;
- эмитенты аттестаций могут ошибаться или быть взломаны (не доверенные сверх бюджета);
- ни один эмитент, включая Мемпаспорт, не подтверждает уникальность человека (ADR-0012).

**Нападающие**: внешний пользователь, спамер, фармер наград, скомпрометированный эмитент, один византийский
валидатор, злонамеренный пир в P2P, локальный сбой диска/процесса.

## 2. Угрозы

| # | Угроза | Защита | Как проверяем |
|---|---|---|---|
| 1 | **Replay** tx в той же сети | Последовательный nonce; аккаунты с `nonce > 0` не удаляются; `expires_at_height` + `max_tx_ttl_blocks` | Unit: повтор tx → `ERR_NONCE`; сценарий: tx после истечения → `ERR_EXPIRED`; tx с TTL > лимита → `ERR_TTL_TOO_LONG` |
| 1a | **Replay между сетями** / между типами подписей | `chain_id` в подписанном теле; prefix-free префиксы подписей (protocol.md §4.4) | Векторы: tx с чужим chain_id → `ERR_CHAIN_ID`; подпись аттестации, поданная как подпись tx → `ERR_SIGNATURE` |
| 2 | **Double spending** | Единый порядок tx от BFT; последовательное исполнение со stateful-проверками после каждой tx; мгновенная финальность | Сценарий: две tx с одним nonce в одном блоке → вторая отклонена; две траты, превышающие баланс → вторая `ERR_INSUFFICIENT_FUNDS`; инвариант supply |
| 3 | **Невалидные подписи**, неканонические подписи, малый порядок, malleability | Строгая проверка (protocol.md §5.2), фиксированная версия libsodium, `tx_id` по полным байтам при каноническом S | Векторы RFC 8032 + граничные векторы с ожидаемым reject; fuzz декодера и проверки |
| 3a | **Слабый или некорректный ключ валидатора** (малый порядок, кручёная компонента, неканоническая кодировка) | Проверка §5.7 (подгруппа простого порядка) при загрузке genesis | Векторы `validator_keys` в `ed25519.json` |
| 4 | **Equivocation валидатора** (двойные голоса) | Safety Tendermint при `f < n/3`; evidence от CometBFT; `priv_validator_state` у честных нод; ручное исключение | M2: localnet с принудительным дублированием ключа → evidence в `FinalizeBlock.misbehavior` и событие |
| 5 | **State divergence** (недетерминизм, баг, разные версии) | Правила детерминизма (architecture.md §6); `app_hash` в следующем заголовке → нода останавливается; единый код для `ProcessProposal` и `FinalizeBlock` | Replay N блоков дважды → одинаковые roots; сравнение roots GCC vs Clang, debug vs release, разные платформы; property-тесты |
| 6 | **Malformed P2P / tx сообщения** | P2P-уровень — CometBFT; tx-байты — строгий YCS-декодер с лимитами до аллокации; ABCI-сокет только локальный (Unix socket) | libFuzzer: декодер tx, аттестаций, Bech32m, ABCI-кадров; корпус из валидных векторов |
| 7 | **Sybil-фарм наград** | Бюджет эмитента за эпоху, Rewards Pool как общий потолок, лимиты на адрес, сумма из каталога, ответственность эмитента | Сценарии: превышение бюджета → `ERR_CLAIM_BUDGET`; пустой пул → `ERR_CLAIM_POOL_EMPTY`; лимит адреса |
| 8a | **Компрометация ключа пользователя** | Шифрованный keystore (Argon2id + XChaCha20-Poly1305), `sodium_memzero`; восстановить средства нельзя — это свойство системы, о нём предупреждаем | Тесты keystore: неверный пароль, повреждённый файл |
| 8b | **Компрометация ключа эмитента** | Ущерб ≤ бюджета эпохи; отзыв ключа/эмитента операцией governance 3-of-5 (после M1); ротация через `key_id` | Сценарий: отозванный ключ → `ERR_CLAIM_ISSUER` |
| 8c | **Компрометация ключа валидатора** | 1 из 4 не ломает safety; ротация ключа через изменение набора governance 3-of-5 (после M1); на mainnet — удалённый signer | M2: остановка одного валидатора, сеть продолжает работу |
| 9 | **Порча хранилища** | LMDB: атомарные транзакции, copy-on-write; узлы SMT адресуются хешем — проверяемы при чтении; `yap verify-state` пересчитывает root из листьев; при расхождении — пересинхронизация от genesis | Тест: убить процесс во время `commit` → после рестарта state = предыдущая высота; ручная порча файла → детект `verify-state` |
| 10 | **Denial of service** | `min_fee`; `max_tx_bytes`; лимит размера блока и mempool в CometBFT; дешёвые stateless-проверки до проверки подписи и state; лимиты RPC (за reverse proxy с rate limit); валидаторы не публикуют RPC, за sentry | Нагрузочный тест localnet (M2): поток мусорных и валидных tx, сеть продолжает производить блоки |
| 11 | **Злонамеренный proposer** (цензура, мусорные блоки, перестановки) | `ProcessProposal` отклоняет блоки с невалидными tx; ротация proposer'а ограничивает цензуру одним раундом; front-running некритичен (нет DEX/контрактов) | Сценарий: блок с невалидной tx → REJECT |
| 12 | **Манипуляция временем блока** (продление аттестаций, эмиссия) | Время блока — по правилам CometBFT (кворумное/ограниченное); эмиссия не зависит от времени; допуск аттестаций ±`attestation_clock_skew_s` | Unit: границы A4 |
| 13 | **Неконтролируемая эмиссия** из-за частоты блоков | Эмиссия фиксирована на блок и ограничена `max_issuance`; параметры CometBFT фиксируются в конфиге сети | Мониторинг высоты/supply на testnet; инвариант `total_minted ≤ max_issuance` |
| 14 | **Supply chain зависимостей** | Точные URL релизов + SHA-256 в CMake (ADR-0018), фиксированная версия CometBFT и libsodium | CI: сборка падает при несовпадении хеша |
| 15 | **Несправедливые награды валидаторам**: византийский proposer не включает чужую подпись в `last_commit` | Ущерб — доля одного блока; ротация proposer'а; мониторинг доли подписей каждого валидатора в `last_commit` | Unit: распределение при неполном `last_commit`; M2: метрика пропусков |
| 16 | **Компрометация ключей governance** (multisig 3-of-5) | Порог 3 из 5, ключи у разных людей и на разных устройствах; любые операции публичны в цепи | Будет специфицировано вместе с операциями governance (после M1) |
| 17 | **Расхождение кодов результатов** (коды входят в `last_results_hash`) | Нормативный порядок проверок (ADR-0019), общий код `ProcessProposal`/`FinalizeBlock` | Векторы `blocks.json` с ожидаемыми кодами каждой tx |
| 18 | **Арифметическое переполнение** | Checked-арифметика везде, классы ошибок (ADR-0017), сравнения без переполнения (`a − b ≤ c` вместо `a ≤ b + c`) | Unit: граничные значения `U64_MAX`; UBSan |

## 3. Остаточные риски

- Две ноды из четырёх недоступны → сеть стоит (safety сохраняется, liveness — нет).
- Сговор 2+ валидаторов ломает safety. В permissioned-сети это решается выбором операторов, а не протоколом.
- Эмитент может честно ошибаться в оценке событий; протокол лишь ограничивает ущерб.
- Ошибка в CometBFT — общая зависимость всех нод; смягчается фиксированием проверенной версии.
