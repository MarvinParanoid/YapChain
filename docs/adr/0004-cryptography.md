# ADR-0004: Ed25519 (libsodium), SHA-256, tagged hashing

**Статус:** PROPOSED

## Контекст
Нужны подписи пользователей, эмитентов и хеши для commitments. Разные реализации Ed25519 по-разному отвечают
на граничные подписи — для блокчейна это источник расхождения state.

## Решение
- Ed25519 (RFC 8032) через **libsodium** с зафиксированной версией; правила проверки явно записаны в protocol.md §5.2
  и закреплены граничными test vectors.
- SHA-256 для всех хешей (совместимо с CometBFT).
- Domain separation: `H_tag(tag, m) = SHA-256(u8(len(tag)) || tag || m)` для хешей и prefix-free префиксы
  `YAPCHAIN/<TYPE>/V1\0` для подписей.

## Альтернативы
- OpenSSL 3 — иная семантика проверки Ed25519, тяжелее.
- BLAKE2b/BLAKE3 — быстрее, но выигрыш не важен при нашей нагрузке; SHA-256 проще аудировать и совпадает с CometBFT.
- secp256k1 — не даёт преимуществ без EVM-совместимости.
- BLS-агрегация — не нужна при 4 валидаторах.

## Последствия
Обновление libsodium допускается только после прохождения набора граничных векторов.
