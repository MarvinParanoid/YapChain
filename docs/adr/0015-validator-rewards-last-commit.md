# ADR-0015: Награды валидаторам и семантика last_commit CometBFT

**Статус:** DECIDED (ревизия M0)

## Проблема
r1 говорил «валидаторы, подписавшие предыдущий блок» без привязки к структуре CometBFT и без правил на высоте 1,
для голосов `Nil` и для несоответствий набора валидаторов.

## Факты о CometBFT (проверить для выбранной версии перед M2)
- `FinalizeBlock.decided_last_commit` (`CommitInfo`) — голоса за блок `H−1`, включённые proposer'ом в блок `H`;
  по записи на каждого валидатора набора `H−1` с `BlockIDFlag` ∈ {Absent=1, Commit=2, Nil=3}.
- На `initial_height` список пуст.
- Состав выбирает proposer (любой набор > 2/3 power плюс успевшие голоса); он часть блока и одинаков для всех нод.

## Решение
- Вознаграждаются только записи с флагом `Commit`; веса — `ValidatorInfo.power` из state; порядок — по возрастанию адреса.
- На высоте 1 валидаторская доля целиком уходит в Treasury (protocol.md §9.5, economics.md §4).
- Неизвестный адрес, повтор адреса или несовпадение power → fail-stop (рассинхронизация с CometBFT).
- Dev-режим M1 воспроизводит ту же семантику (пусто на высоте 1).

## Последствия
Византийский proposer может лишить одного валидатора награды за один блок (threat-model.md №15) — приемлемо для testnet.
