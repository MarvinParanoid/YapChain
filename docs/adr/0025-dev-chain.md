# ADR-0025: Локальная dev-цепочка

**Статус:** DECIDED (M1.4) · реализует protocol.md §14; только для локальной разработки

## Решение
- Один доверенный производитель (ключ назначения `dev-producer`, ADR-0024) подписывает `DevBlock` (§14).
  Публичный ключ производителя записывается при `dev init` (метаданные `yapchain/dev`) и далее не меняется.
- **Любой** блок — свой или импортированный — проходит одну и ту же проверку по порядку: версия, chain_id,
  высота (уже есть → `AlreadyHave`, пропуск → `HeightGap`), хеш предыдущего блока (для высоты 1 — `genesis_hash`),
  время (высота 1: ≥ времени genesis; дальше строго больше предыдущего), ключ производителя, подпись,
  `tx_root`, все транзакции `OK`, `state_root`. Нарушение — отказ всего блока, состояние не меняется.
- Принятый блок записывается в таблицу `blocks` **в той же транзакции LMDB**, что и состояние высоты
  (`Engine::commit` с дополнительными операциями): после сбоя блок и состояние не могут разойтись.
- Контекст блока: `last_commit` пуст на высоте 1, дальше — все валидаторы genesis с флагом Commit;
  proposer — первый валидатор по адресу (§14).
- Время по умолчанию — предыдущее + 2000 мс, а не системные часы: цепочка воспроизводима.
- Replay журнала: совпадающие уже сохранённые блоки пропускаются, отличающиеся — `Conflict`.
- `dev init` на инициализированной базе: тот же genesis и производитель → ничего не делает; иначе — ошибка.
  Существующая цепочка никогда не перезаписывается.

## Ограничения
Dev-цепочка не заменяет BFT-консенсус и не используется в testnet: у неё нет голосований и доверие к
производителю абсолютное (в пределах правил исполнения, которые проверяются полностью).
