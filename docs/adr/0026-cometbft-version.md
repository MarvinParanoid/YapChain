# ADR-0026: Версия CometBFT для M2

**Статус:** DECIDED (M1.5) · уточняет [ADR-0002](0002-consensus-engine.md)

## Факты (проверены по тегам репозитория cometbft/cometbft и политике Cosmos, ноябрь 2026)
| Линия | Последний тег | Дата | Статус |
|---|---|---|---|
| v0.40.x | v0.40.0 | 2026-07-27 | поддерживается, семейство релизов 2026.1 |
| v0.38.x | v0.38.26 | 2026-08-13 | поддерживается, семейство 2025.1 |
| v0.39.x | v0.39.4 | 2026-07-28 | не входит в семейство релизов |
| v1.x | v1.0.1 | 2025-02-03 | **отозвана, не поддерживается** |

v0.39/v0.40 — потомки линии v0.38 (не v1). Проводной протокол ABCI 2.0 (`proto/tendermint/abci/types.proto`,
пакет `tendermint.abci`) одинаков для v0.38.26 и v0.40.0 во всех используемых нами методах.

## Решение
- **Основная версия: CometBFT v0.40.0** (тег `06b4cbf4b776554bd2b95fc39c80991e7529e765`) — новейшее поддерживаемое
  семейство, самое длинное окно поддержки.
- **Запасная: v0.38.26** — максимальная зрелость; совместима по проводу, если не использовать `InsertTx`/`ReapTxs`
  (они нужны только для app-mempool).
- Перед стартом M2 проверить, не вышел ли v0.40.x patch-релиз, и взять последний.

## Важные следствия (подробно — docs/cometbft-compatibility.md)
- Спецификация `spec/abci/*.md` на теге v0.40.0 частично устарела (скопирована из v1: lanes, PBTS, `next_block_delay`
  — этого в коде v0.40.0 нет). Источники истины: proto на теге, код, и спецификация v0.38.26.
- Время блока — BFT time; интервал задаётся `timeout_commit` в конфиге ноды (не консенсус-параметром).
- `last_results_hash` хеширует `code`, `data`, `gas_wanted`, `gas_used` (не `codespace`, хотя спецификация пишет иное).
