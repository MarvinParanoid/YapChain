# ADR-0006: State root — Sparse Merkle Tree

**Статус:** PROPOSED

## Контекст
Нужен `app_hash`, который не зависит от реализации и порядка вставки, дешево обновляется и даёт доказательства
для будущих explorer/кошелька.

## Решение
Двоичное SMT глубины 256 с «схлопыванием» поддеревьев из одного листа (protocol.md §8.1): `EMPTY` = нули,
лист и узел хешируются разными тегами. Ключ пути — `H_tag("YAP/state-key/v1", raw_key)`.

## Альтернативы
- Пересчёт Merkle по отсортированным листьям на каждом блоке — проще, но O(n) на блок.
- Полное SMT без схлопывания — 256 хешей на обновление.
- IAVL, Merkle Patricia Trie — сложнее в спецификации и реализации.
- Jellyfish Merkle Tree (16-арное) — эффективнее на больших объёмах, но сложнее; не нужно для testnet.

## Последствия
O(log n) хешей на обновление; доказательства включения и невключения. Узлы хранятся по хешу, что позволяет
проверять целостность при чтении. Pruning старых версий — позже.
