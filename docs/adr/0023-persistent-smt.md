# ADR-0023: Персистентный SMT и проверка состояния

**Статус:** DECIDED (M1.3) · реализует [ADR-0006](0006-state-commitment-smt.md); нормативный корень — protocol.md §8.1 без изменений

## Контекст
В M1.2 `state_root` пересчитывался по всем листьям на каждом блоке: O(n log n), десятки миллисекунд уже при 10⁵
записях. Нужны обновление за O(глубина) и хранение узлов на диске атомарно вместе с состоянием.

## Решение
- Узлы адресуются своим хешем и хранятся в таблице `smt` (ADR-0022), отдельно от консенсусного state.
  Лист — `0x00 ‖ key ‖ value_hash`, внутренний узел — `0x01 ‖ left ‖ right`; пустое поддерево (нулевой хеш) не хранится.
- Дерево всегда в канонической компактной форме §8.1: поддерево с одним листом — это сам лист. Поэтому хеш
  совпадает с полным пересчётом при любом порядке операций (проверяется property-тестами и векторами).
- Обновление идёт по одному пути: вставка расщепляет лист (существующий лист опускается без перезаписи),
  удаление схлопывает поддерево с одним оставшимся листом вверх.
- Заменённые узлы удаляются в той же транзакции. Это безопасно: в одной версии дерева каждый узел встречается
  ровно один раз (хеш листа включает полный ключ; внутренние узлы не меняют позицию). Тесты проверяют, что
  после каждого блока число хранимых узлов равно числу достижимых — нет ни потерянных, ни лишних.
- История версий не хранится (только последнее состояние). Pruning и доказательства для прошлых высот — позже.

## Проверка (`verify-state`)
Полная проверка: каждый достижимый узел существует, декодируется, хешируется в свой ключ, стоит на позиции,
согласованной с битами ключа, внутренние узлы покрывают ≥ 2 листьев; множество листьев совпадает с консенсусным
state; нет лишних узлов; корень совпадает с метаданными и с полным пересчётом; выполнены инварианты §7.3.
