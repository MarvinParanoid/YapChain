# ADR-0010: Строгая проверка блоков и детерминированный пропуск tx

**Статус:** PROPOSED

## Контекст
Блок может содержать невалидные tx (баг или злонамеренный proposer). Возможны два подхода: включать такие tx
с платой за ошибку или не допускать их вовсе.

## Решение
1. `PrepareProposal` включает только tx, прошедшие последовательную симуляцию.
2. `ProcessProposal` отклоняет предложение целиком, если хотя бы одна tx невалидна.
3. `FinalizeBlock` (решённый блок; full nodes исполняют только его) пропускает невалидную tx без изменения state
   и с кодом ошибки — детерминированно на всех нодах.
4. Невалидная tx не платит комиссию и не увеличивает nonce.

## Последствия
Модель «tx либо применена целиком, либо не существует» проста для кошелька и тестов. Шаг 3 срабатывает лишь
при сговоре ≥ 1/3 валидаторов или баге, и даже тогда не приводит к расхождению.
