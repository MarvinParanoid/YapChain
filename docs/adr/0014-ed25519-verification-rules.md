# ADR-0014: Нормативный алгоритм проверки Ed25519

**Статус:** DECIDED (ревизия M0) · уточняет [ADR-0004](0004-cryptography.md)

## Проблема
В r1 protocol.md правило проверки звучало как «совпадает с libsodium» плюс неформальный список. Этого
недостаточно: независимая реализация (кошелёк, explorer, другая нода) не может воспроизвести поведение по такому
описанию, а реализации Ed25519 расходятся именно в граничных случаях (неканонический S, точки малого порядка,
ключи смешанного порядка, cofactored vs cofactorless уравнение).

## Решение
protocol.md §5.2 задаёт пошаговый алгоритм: `S < L`; отказ при `y(R) mod p ∈ SMALL_Y`; отказ при `y(A) ≥ p` или
`y(A) ∈ SMALL_Y`; cofactorless-уравнение с побайтным сравнением кодировки `R`. `SMALL_Y` перечислен явно.
Алгоритм выбран так, чтобы совпадать с `crypto_sign_verify_detached` libsodium (без `ED25519_COMPAT`).

## Проверка
`tools/refgen` содержит независимую реализацию этого алгоритма на Python (без libsodium) и генерирует
`test-vectors/ed25519.json` с граничными случаями: `S ≥ L`, A/R малого порядка, неканонический A, неканонический R,
ключ смешанного порядка при `k ≡ 0 (mod 8)` (принимается) и при `k ≢ 0` (отклоняется — признак cofactorless).
C++-тесты требуют совпадения libsodium с векторами.

## Последствия
Обновление libsodium допускается только при прохождении векторов. Смена семантики — только новым ADR и
новой версией протокола.
