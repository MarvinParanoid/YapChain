# ADR-0007: Хранилище состояния — LMDB

**Статус:** PROPOSED

## Контекст
Нужны атомарная запись состояния блока, устойчивость к падениям и минимум операционной сложности.
Блоки хранит CometBFT; наше хранилище — только state, узлы SMT и результаты tx.

## Решение
LMDB за интерфейсом `KvStore`. Одна write-транзакция LMDB на каждый `Commit`.

## Альтернативы
- **RocksDB** — стандарт индустрии, checksum'ы блоков, лучше под большую запись; но тяжёлая сборка и тюнинг компакций.
  Остаётся заменой без изменения state machine, если LMDB упрётся в производительность.
- SQLite — избыточен как SQL, медленнее как KV.

## Последствия
- (+) ~10 тыс. строк C, ACID, copy-on-write, crash-safe без WAL-тюнинга.
- (−) Нет checksum'ов страниц — компенсируется проверкой узлов SMT по хешу и `verify-state`.
- (−) Нужно задавать `map_size` с запасом.
