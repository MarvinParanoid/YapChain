# ADR-0019: Нормативный порядок проверок транзакций

**Статус:** DECIDED (ревизия M0)

## Проблема
Код результата tx входит в консенсусный хеш результатов CometBFT (`last_results_hash`, поля `code/data/gas_*`).
Если tx нарушает несколько правил сразу, разные реализации могли вернуть разные коды → расхождение хеша.
Кроме того, в r1 проверка подписи стояла в середине списка (до дешёвых проверок payload), а в attestations.md
проверки nonce/срока (A11) стояли после правил claim, противореча protocol.md.

## Решение
- Проверки выполняются строго по номерам: S1…S11 (подпись — последняя), затем T1…T7; внутри T7 — A1…A10.
- Возвращается код первой нарушенной проверки.
- Неизвестный тег payload — `ERR_DECODE` (S2).
