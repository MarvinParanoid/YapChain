# ADR-0003: Каноническая сериализация YCS

**Статус:** PROPOSED

## Контекст
Хеши и подписи требуют ровно одного байтового представления каждого значения, одинакового на всех платформах и компиляторах.

## Решение
Собственный формат YCS (protocol.md §3): little-endian целые фиксированной ширины, `u32`-префиксы длин,
`u8`-теги enum/option, строгий декодер (без лишних байт, лимиты до аллокации). Совпадает с подмножеством Borsh.

## Альтернативы
- Protobuf — не каноничен (порядок полей, varint-неоднозначности, неизвестные поля).
- CBOR (deterministic profile) — сложнее и шире, чем нужно.
- JSON — неоднозначен (числа, пробелы, порядок ключей).
- Borsh-библиотека — поддерживаемой C++-реализации нет; формат простой, проще описать и реализовать самим (~300 строк).

## Последствия
Варинтов нет, поэтому неминимальных кодировок нет. JSON используется только на границах (genesis, CLI) и
никогда не хешируется напрямую.
